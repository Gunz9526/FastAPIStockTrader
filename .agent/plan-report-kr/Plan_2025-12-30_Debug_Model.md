# 모델 학습 및 데이터 수 조사 계획

## 목표
1.  학습 성공 로그에도 불구하고 로컬 호스트에 모델 파일이 생성되지 않는 원인을 규명합니다.
2.  2년치 데이터인데 학습 샘플이 449개로 적게 나오는 이유를 명확히 확인합니다.

## 문제 분석
1.  **모델 파일 누락**:
    - `docker-compose.yml`에 `.:/app` 볼륨이 마운트되어 있으므로 컨테이너 내 `/app/model_artifacts`에 생성된 파일은 호스트에도 보여야 정상입니다.
    - **가설**: 권한 문제(root 소유), 경로 문제, 또는 컨테이너 내부 경로와 호스트 경로의 매핑 오해 가능성.

2.  **적은 데이터 수 (449개)**:
    - 2년치 거래일 수: 약 252일/년 × 2년 ≈ 504일.
    - `FeatureEngineer`에서 사용하는 기술적 지표 중 `SMA(50)`은 초반 50개의 데이터를 NaN으로 만듭니다 (`dropna`로 제거됨).
    - 예상 샘플 수: 504 - 50 = 454개.
    - 실제 샘플 수 449개는 예상치와 매우 근접하므로, **데이터가 부족한 것이 아니라 정상적인 전처리 결과**일 가능성이 매우 높습니다.

## 진행 계획

### 1. 컨테이너 내부 파일 확인
- `worker` 컨테이너 내부에서 `ls -la model_artifacts/` 명령을 실행하여 파일 생성 여부와 권한을 직접 확인합니다.

### 2. 데이터 수 검증 스크립트 작성 (`scripts/debug_data_count.py`)
- DB에서 해당 종목의 전체 OHLCV 개수를 조회합니다.
- `FeatureEngineer` 로직을 동일하게 수행하여 몇 개의 행이 `dropna`로 제거되는지 정확히 계산합니다.
- 이를 통해 사용자에게 "데이터 부족"이 아닌 "지표 계산을 위한 초기 데이터 소모"임을 증명합니다.

### 3. 해결책 적용
- 권한 문제일 경우: Dockerfile에서 유저 권한 조정 또는 코드에서 파일 권한 설정.
- 경로 문제일 경우: 절대 경로 사용.

## 검증
- `scripts/debug_data_count.py` 실행 결과 리포팅
- 모델 파일의 호스트 생성 확인
